# Architecture

## Stack

- **Expo SDK 58**, React Native 0.88, React 19.3, TypeScript (strict), **React Compiler on**
  (`experiments.reactCompiler` in `app.json`), typed routes.
- **expo-router** (file-based routes in `src/app/`) with one root `Stack`. Native headers are hidden; screens draw
  their own `Header`.
- `react-native-reanimated` 4 for animations, `react-native-svg` for the progress ring and QR code.
- Storage: `@react-native-async-storage/async-storage` (localStorage on web).
- Other modules: `expo-localization` (default language), `expo-file-system`
  (new `File` / `Paths` API) + `expo-sharing` + `expo-document-picker` (transfer files), `expo-clipboard`,
  `expo-haptics`, `expo-image`, `react-native-qrcode-svg`, `fflate` (deflate), `@expo/vector-icons` (Ionicons).
- Path alias: `@/*` → `src/*`, `@/assets/*` → `assets/*`.

## State

- `AppProvider` (`src/lib/store.tsx`) holds `settings` and `progress`.
  - `Settings`: `lang`, `state` (federal state code), `practiceTranslations`, `theme`, `onboarded`.
  - `Progress`: `stats: Record<questionId, QStat>`, `exams: ExamRecord[]`, `updatedAt`.
  - It loads from AsyncStorage once (`ready`), then saves with a 300 ms debounce on every change.
  - Mutations: `updateSettings`, `recordAnswer`, `toggleStar`, `addExam`, `replaceProgress`, `resetProgress`.
- **Transient state lives in modules, not the store**: the running exam (`exam-session.ts`), the practice list
  order (`practice.ts`). They are lost on reload by design; screens redirect if their session is missing.

## Theming

- `useTheme()` returns `{ c, dark }`. `c` is the palette (`bg`, `surface`, `surfaceAlt`, `text`, `textMuted`, `border`,
  `primary` sage green, `accent` sand, `success`, `danger`, each with a `*Soft` variant).
- The mode comes from `settings.theme` (`system` follows the OS).
- Always use palette tokens and `space` / `radius`. Don't hard-code colors. Exception: the QR code and question
  images sit on white for contrast.
- Content is centered with `maxContentWidth` (720) so web/tablet stay readable.

## i18n

- UI strings: `src/lib/i18n.ts`. `en` is the source of truth for keys (`StringKey`); `de` must have every key
  (TypeScript enforces it). Use `useT()` in components and `translate(lang, key, params)` outside React.
  Placeholders look like `{count}`.
- The exam screens use `translate('de', …)` on purpose, because the simulator chrome is always German.
- Question translations: `src/data/translations/<lang>.json`, registered in the `translations` map in `questions.ts`.
- **Adding a language:** add a dictionary + `LANGUAGES` entry in `i18n.ts`, add the translations JSON, and register it.
  `stateName()` only knows `de` / `en` names, so extend `STATES` too. For RTL languages, check layout direction.

## Components to reuse

- `Screen` (scroll + safe area + optional `header` / `footer`), `Header` (back button + title + right slot).
- `Button` kinds: `primary`, `secondary`, `ghost`, `danger`. Long labels wrap badly in side-by-side buttons on
  phones, so stack buttons vertically when labels are long.
- `Bilingual de tr show`: the one place that defines how translations look. Reuse it.
- `useDialog().confirm({ message, okLabel, cancelLabel, destructive })` / `notify(message)`.

## Platform notes

- Web: `Platform.OS === 'web'` branches for file download (Blob link), reading transfer links from
  `location.hash`, the `<Head>` tags and service-worker registration in `_layout.tsx` (web production only).
- Haptics only on native.
- `app.json` → `web.output: "static"`, `experiments.baseUrl: "/app"` (the web app lives under `/app/`; keep
  `WEB_BASE` in `src/lib/config.ts` and `public/manifest.webmanifest` in sync).
- `public/` (manifest, service worker, PWA icons) is copied to the web export root. The landing page is separate,
  in `landing/`, and both are combined by `scripts/build-site.mjs`; see [deployment.md](deployment.md).
- No runtime permissions on Android (the camera module was removed for F-Droid).
- `android/` (and `ios/`) are not committed. They are generated (CNG) if you run a native build. There's no `ios`
  section in `app.json`, because iOS is served by the PWA.
